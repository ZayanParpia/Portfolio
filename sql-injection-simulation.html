Proof of Concept Report

This simulation acts as a Proof of Concept (PoC) for detecting SQL injection (SQLi) attacks inside a home lab. The primary objective is to configure an Apache reverse proxy to channel traffic to a vulnerable web server, consolidate the proxy logs into the Wazuh agent, and build custom rule detection logic that fires alert triggers upon detecting suspicious query patterns.

Attack payloads (such as SQL keywords, UNION SELECT attempts, and boolean logic expressions like OR 1=1) are sent via curl and browser forms, logging the requests in the Apache access logs, which are then analyzed dynamically by Wazuh.

What I Learned

Developing this Proof of Concept simulation provided key insights into web application log analysis and security monitoring configurations:

Technical Skills
  • Apache Proxy Configurations: Implementing reverse proxy parameters in site configurations to route network traffic securely.
  • Wazuh Agent Log Scopes: Configuring the local agent's ossec.conf to target specific log files and parse them using predefined log decoders (web-accesslog).
  • Custom XML Rule Writing: Utilizing logical tags (<match>, <if_sid>, <decoded_as>) to write correlation logic for detection engineering.
Security Concepts
  • Exploiting Public-Facing Applications (MITRE T1190): Analyzing request patterns to understand vulnerabilities in input handling of public ports (80/443).
  • Built-In vs. Custom Threat Rules: Discovering that enterprise SIEM systems come pre-configured with rulesets, and evaluating the necessity of tuning custom signatures vs using default rules.
