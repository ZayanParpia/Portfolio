Platform: AWS  •  Infrastructure as Code: Terraform  •  Focus: Cloud Security & DevSecOps

Multi-AZ AWS Architecture

Public traffic passes through AWS WAF and an Application Load Balancer before reaching web servers in private EC2 subnets. NAT supports controlled outbound access, while monitoring, encryption, and SSM provide operational and security controls.

Traffic and Operations Flow

Internet -> AWS WAF -> Application Load Balancer -> Private EC2
Admin -> SSM Session Manager -> Private EC2
Private EC2 -> NAT Gateway -> Internet
AWS Resources -> CloudWatch / VPC Flow Logs -> Private S3

Terraform Workflow

terraform init
terraform fmt
terraform validate
terraform plan
terraform apply

The infrastructure is managed as code for repeatable planning and deployment. Use terraform destroy when the environment should be removed.

Project Overview

This project builds a production-style AWS web application environment with Terraform. Its public entry path is AWS WAF -> Application Load Balancer -> private EC2 web servers, deployed across multiple Availability Zones for redundancy.

The design keeps application instances off the public internet, uses Systems Manager Session Manager instead of SSH for administration, and combines least-privilege IAM, KMS encryption, private S3 storage, CloudWatch, and VPC Flow Logs.

Security Design

  • Controlled ingress: WAF and the ALB are the public entry path; application instances remain in private subnets.
  • Restricted administration: SSM Session Manager replaces exposed SSH access.
  • Least privilege: IAM roles and policies follow the Principle of Least Privilege.
  • Protected data: Private S3 buckets use Block Public Access, with KMS for encryption at rest.
  • Visibility: CloudWatch and VPC Flow Logs support operational monitoring and network investigation.
