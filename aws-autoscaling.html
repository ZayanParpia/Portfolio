VPC Configuration

Custom VPC created for the project, isolating all resources within a private network boundary.

Internet Gateway

Internet Gateway attached to the VPC, enabling the ALB in public subnets to receive inbound traffic from the internet.

Routing Table

Route table configured to direct internet-bound traffic through the Internet Gateway while keeping EC2 instances isolated in private subnets.

Subnets — AZ1 & AZ2

Two public subnets in separate Availability Zones host the ALB for high availability. EC2 instances are deployed into private subnets to reduce exposure.

Application Load Balancer (ALB)

Active ALB spanning both Availability Zones, performing health checks and distributing traffic only to healthy EC2 targets registered in the Target Group.

Project Overview

This project demonstrates a production-ready AWS architecture built around an EC2 Auto Scaling Group (ASG). It handles changing traffic, maintains availability across multiple Availability Zones, and applies cloud security best practices.

An Application Load Balancer distributes HTTP traffic to EC2 instances in private subnets. IAM least-privilege roles and SSM Session Manager control instance access without exposing SSH ports.

Key Learnings

  • Scalability & Resilience: Auto Scaling is not just about performance; it is a resilience mechanism that helps keep services available during failures.
  • Defense-in-Depth: Security must be designed at every layer, including private subnets, security groups, IAM, and limiting SSH exposure.
  • Least Privilege IAM: Writing a scoped IAM policy reinforced why broad permissions are dangerous in production environments.
  • CLI Automation: Using the AWS CLI made the workflow faster, consistent, and reproducible.
